# 创作工作台 A 方案设计

## 目标

将现有 AI 小说到视频系统统一为专业创作控制台。保留现有业务接口、元素 ID、请求参数、数据格式和页面功能，仅重构信息架构、视觉层级、响应式布局与状态反馈。

视觉方向采用“镜头剪辑台”：深石墨导航、暖白工作画布、苔绿状态强调、橙色仅用于高风险或生成动作。它应更像剪辑与制作软件，而不是营销页或普通表单集合。

## 全局结构

- 左侧为固定、紧凑的工作区导航：小说大纲、小说全文、历史作品、分镜脚本、视频创作、资产库、模型管理。
- 顶部上下文栏统一显示当前作品、当前章节（如适用）、保存状态与任务入口；长标题允许换行但不挤压操作区。
- 主区域承载当前页面的核心任务；次要信息进入可折叠侧栏、详情抽屉或底部任务区，不再占用固定右侧空白栏。
- 所有页面共用状态样式：加载中、空状态、已保存、生成中、成功、失败、可重试；状态消息必须紧邻关联操作。
- 宽度不足时，主编辑区优先保留；次级栏移到下方或折叠为抽屉，不产生横向溢出、窄按钮或漂浮遮挡。

## 页面信息架构

### 小说大纲工作台

- 左侧：小说设定表单，按“基础定位、角色与世界、故事结构”分组，使用可折叠分段减少首次认知压力。
- 主区：生成结果、整体梗概、伏笔、章节列表。未生成时显示结果空态和明确的生成动作；生成后显示“下一步：生成全文”。
- 生成任务状态显示在结果标题行，不另占右侧任务栏。

### 小说全文工作台

- 三栏稳定工作区：可滚动章节目录、正文阅读/编辑区、分镜操作面板。
- 分镜面板重点展示当前章节的镜头数量、生成状态、进入分镜/视频的下一步；视觉风格配置收进可折叠“全局视觉设定”。
- 章节目录拓宽，正文宽度限制为舒适阅读列，分镜栏保留足够宽度以读取脚本内容。

### 历史作品

- 作品采用项目卡片或紧凑列表：标题、章节数、生成阶段、更新时间和主要动作在同一行/卡片中。
- 选择作品是主要动作；复制概览和删除归入更多操作，防止多按钮挤压。
- 当前选中作品应持续同步至全文工作台；切换作品时清除旧的分镜/视频上下文。

### 分镜脚本工作台

- 顶部放置作品选择和 TXT/DOCX 导入；历史作品入口作为同一上下文区的替代路径。
- 中央使用镜头序列，选中镜头进入编辑面板；脚本、人物/场景资产、首帧操作根据当前镜头在同一工作流中切换。
- 当前镜头的脚本、资产关联、生成首帧和状态必须在首屏可见，较长配置折叠为次级区域。

### 视频创作工作台

- 每个分镜是一个可展开的“生成单元”：镜头描述、首帧缩略图、分辨率、生成/上传/选择视频、任务状态和重试在单元内。
- 生成按钮进入固定的操作行，不随页面滚动覆盖脚本内容。
- 失败状态显示失败原因、重试入口和相关配置；空状态提示用户先从历史作品选择小说，再从全文工作台进入视频生成。

### 资产库

- 左侧筛选（作品、类型、搜索）；中间为自适应资产网格；右侧详情改为按需出现的抽屉/面板。
- 卡片以三视图预览、名称、类型、关联镜头数量为核心信息；复用、覆盖和预览从详情操作区执行。

### 模型管理

- 文本、图像、视频三种配置按并列但独立的配置卡展示。
- 卡片首部显示启用状态与服务商；测试结果在对应卡片内显示，不在页面顶部堆叠长错误文本。
- API Key 保持加密存储行为；错误需说明是地址、鉴权、服务商连通性还是查询地址配置问题。

## 状态与交互

- 加载中：展示当前加载对象，例如“正在载入《救场小说》第 2 章”，避免永久显示“正在加载”。
- 空状态：说明缺少什么上下文，并提供单个可执行去向；不同时展示互相矛盾的加载提示。
- 生成中：显示阶段、百分比/轮询状态与可安全离开的提示。
- 失败：使用局部错误卡，保留原错误文本和重试动作；不遮挡其他内容。
- 成功：在操作附近显示已保存/已完成，并更新相应卡片状态。

## 技术边界

- 不修改后端接口、数据库结构、请求参数、原有元素 ID 或业务脚本的契约。
- 继续使用已有的新版页面路由与旧页面回退机制；旧页面不删除。
- 优先新增统一的设计令牌与组件样式，逐页替换布局类名；必要时以最小适配层保持旧 JavaScript 查询节点可用。
- 为每个页面保留静态结构检查，并在视觉改造后运行现有前端检查和 Maven 打包验证。

## 验收标准

- 任一工作台在 1440px 宽度下没有横向溢出、纵向文字按钮或悬浮遮挡。
- 分镜和视频页的关键动作、当前脚本、首帧与状态无需在首屏外寻找。
- 960px 和 720px 以下能按主次顺序堆叠，按钮不会挤压成窄列。
- 所有现有页面可继续加载真实数据并保持已有操作可用。
