# 小说人物与场景三视图资产设计

## 1. 目标

在现有小说正文页中，根据当前章节已经生成的分镜脚本，识别人物和场景，生成可编辑的正面、侧面、背面三视图提示词，并在同一部小说内跨章节复用已有资产。

第一版只生成和保存提示词，不直接生成图片；页面保留图片占位和状态，为后续接入图片模型做准备。

## 2. 非目标

- 第一版不接入真实图片生成模型。
- 第一版不做手机端布局。
- 不在每个分镜中重复创建人物和场景资产。
- 不把不同小说中同名人物或场景自动合并。

## 3. 页面布局

正文页保持桌面端三列布局：

```text
┌────────────┬────────────────────┬──────────────────────────┐
│ 章节目录   │ 章节正文           │ 分镜脚本 / 人物场景资产 │
│            │                    │                          │
│            │                    │ [分镜脚本]               │
│            │                    │ 分镜列表                 │
│            │                    │                          │
│            │                    │ [人物与场景资产]         │
│            │                    │ 三视图提示词与占位图     │
└────────────┴────────────────────┴──────────────────────────┘
```

第三列通过两个 Tab 切换：

- 分镜脚本：显示当前章节分镜、人物/场景关联标签和提取按钮。
- 人物与场景资产：显示当前小说资产库，可按人物、场景筛选。

## 4. 资产范围和去重规则

资产的复用范围是同一部小说，不跨小说复用。

资产基础识别依据：

```text
novelId + assetType + normalizedName + coreFeatures
```

其中：

- `assetType`：`CHARACTER` 或 `LOCATION`。
- `normalizedName`：标准化后的资产名称。
- `coreFeatures`：人物或场景的核心特征。

AI 识别出当前章节实体后，先查询当前小说资产库：

- 命中已有资产：建立分镜与资产的关联，不重复生成。
- 未命中资产：创建新资产，并生成三组提示词。
- 用户发现误识别：可以编辑名称和特征，或将资产合并到已有资产。

## 5. 版本规则

同一个人物或场景发生明显变化时，不覆盖旧资产，而是创建新版本。

示例：

```text
林澈 v1：普通工程师
林澈 v2：受伤后的工程师
林澈 v3：装备强化后的工程师
```

每个版本独立保存：

- 核心特征
- 正面提示词
- 侧面提示词
- 背面提示词
- 状态

历史分镜保留原版本关联，新分镜可以选择新版本。

## 6. 数据流

```text
当前章节分镜脚本
        ↓
用户点击“提取人物/场景”
        ↓
创建异步任务
        ↓
AI 识别本章人物和场景
        ↓
查询当前小说资产库
        ↓
已有资产：直接复用
新资产：生成三组提示词并保存
        ↓
返回本章资产关联和资产状态
```

提取范围只限当前章节，但查询和复用范围是整部小说。

## 7. 异步任务

由于章节正文较长、资产数量不固定，第一版采用异步任务加前端轮询，不让页面长时间阻塞等待。

启动任务返回：

```json
{
  "taskId": "asset-task-1001",
  "status": "PROCESSING",
  "message": "正在识别本章人物和场景"
}
```

任务状态：

```json
{
  "taskId": "asset-task-1001",
  "status": "COMPLETED",
  "total": 5,
  "reused": 3,
  "created": 2,
  "failed": 0
}
```

状态值：

- `PENDING`
- `PROCESSING`
- `COMPLETED`
- `PARTIAL_FAILED`
- `FAILED`

前端轮询间隔建议为 1.5 至 2 秒，完成、失败或超时后停止轮询。

## 8. 资产接口约定

```text
POST /api/novel/{novelId}/chapters/{chapterNum}/assets/extract
启动当前章节资产提取任务

GET /api/asset-tasks/{taskId}
查询资产提取任务状态

GET /api/novel/{novelId}/assets
查询当前小说全部资产

GET /api/novel/{novelId}/assets/{assetId}
查询资产详情

PUT /api/novel/{novelId}/assets/{assetId}
修改资产名称、特征、版本信息和三组提示词

POST /api/novel/{novelId}/assets/{assetId}/merge
将资产合并到已有资产

GET /api/novel/{novelId}/chapters/{chapterNum}/assets
查询本章关联的资产
```

资产详情示例：

```json
{
  "assetId": 12,
  "novelId": 1,
  "assetType": "CHARACTER",
  "assetName": "凌程",
  "version": 1,
  "coreFeatures": "年轻工程师、黑发、深色短衫",
  "frontPrompt": "人物正面三视图设定图……",
  "sidePrompt": "人物侧面三视图设定图……",
  "backPrompt": "人物背面三视图设定图……",
  "status": "PROMPT_READY",
  "reuseCount": 8
}
```

分镜只保存关联关系，不复制资产内容：

```json
{
  "sceneId": 1,
  "characterAssetIds": [12, 15],
  "locationAssetIds": [8]
}
```

## 9. 前端状态和交互

资产卡片支持：

- 查看名称、类型、版本和核心特征。
- 编辑三组提示词。
- 保存修改。
- 选择合并到已有资产。
- 查看被哪些章节和分镜复用。

三视图区域状态：

```text
未提取
识别中
提示词已生成
提示词生成失败
图片待生成
图片生成中
图片生成成功
图片生成失败
```

第一版图片区域显示“图片待生成”占位状态，并展示对应提示词。后续接入图片模型时，图片生成按钮和结果可以直接挂接到该区域。

## 10. 错误处理

- 当前章节没有分镜：提示“请先生成分镜脚本”。
- 当前章节没有正文：禁止启动提取任务。
- AI 返回格式错误：任务标记失败，记录错误原因，允许重试。
- 部分资产失败：保留成功资产，任务状态为 `PARTIAL_FAILED`，支持只重试失败项。
- 重复点击：同一小说、同一章节存在进行中的任务时，直接返回原任务 ID。
- 用户切换章节：停止当前页面轮询，但后台任务继续；再次进入章节时读取任务状态。
- 合并资产：要求用户确认，合并后保留原资产的历史版本或关联记录。

## 11. 验证范围

第一版至少验证：

1. 当前章节能够提取人物和场景。
2. 已存在资产不会重复创建。
3. 新资产拥有正面、侧面、背面三组提示词。
4. 同一资产可以被多个章节和多个分镜复用。
5. 资产修改后，后续分镜读取到最新版本。
6. 资产版本变化不会破坏历史分镜关联。
7. 异步任务失败、部分失败和重复提交状态正确。
8. 页面刷新后可以恢复任务状态和资产展示。
