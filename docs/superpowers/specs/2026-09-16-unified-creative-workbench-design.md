# 统一 AI 视频创作工作台设计说明

## 目标

在不改变现有后端接口、异步任务语义和核心业务能力的前提下，将项目的所有创作相关页面重组为同一套“项目工作台”体验。页面需要支持项目选择、章节浏览、人物/场景资产管理、分镜编辑、首帧生成与上传、视频生成、历史版本查看以及错误恢复。

本次改造的重点不是换颜色，而是重新定义信息层级、页面布局和操作路径：让用户在同一个作品上下文中连续完成“选择章节 → 提取资产 → 编辑分镜 → 生成首帧 → 生成视频 → 查看任务结果”。

## 范围与约束

- 保留现有页面 URL，兼容旧入口和带 `novelId`、`chapterNum` 的深链接。
- 不删除旧页面；替换前的页面继续以 `.legacy.html` 或 `.legacy.js` 形式保留。
- 不修改后端接口契约，前端继续使用现有 `/api/novel`、`/api/visual-assets`、`/api/video-tasks`、`/api/first-frame-tasks` 等接口。
- 保留现有功能：小说导入、大纲生成/保存、作品删除、章节查看、视觉风格生成/保存、资产提取、资产编辑、三视图生成、资产复用、分镜生成/保存、首帧上传/生成、视频生成/上传/历史版本、安全改写和任务轮询。
- 允许调整组件归属：资产和任务可以从独立页面整合到工作台右侧面板或抽屉；视频生成可以整合到分镜工作区；历史页保留为入口但不再承担主要编辑职责。

## 方案选择

采用“保留路由的统一工作台壳层”。每个 URL 仍是一个可直达页面，但共享导航、项目上下文、状态面板、按钮、卡片、抽屉和错误反馈组件。这样可以获得单页工作台的信息连续性，同时保留现有浏览器历史、后端路由和测试入口的兼容性。

不采用完全单页应用，因为当前项目是静态 HTML + 原生 JavaScript，全面引入路由框架会扩大改造范围并增加任务状态迁移风险；不采用全部弹窗化，因为分镜脚本和视频结果需要较大的连续编辑画布。

## 信息架构

### 全局工作台壳层

桌面端使用三列结构：

1. 左侧工作区导航：作品、章节、资产、分镜、视频、历史。
2. 中间主画布：当前页面的核心内容，始终保留足够宽度给脚本、时间线和预览。
3. 右侧上下文检查器：当前选中资产、生成任务、错误详情和轻量设置；没有选中内容时显示空状态，不抢占主画布。

顶部显示当前作品、章节、生成状态和全局任务入口。底部操作带只承载当前区域的主操作，避免按钮分散在卡片底部或窄侧栏中。

### 页面职责

#### 项目历史/首页

作为作品入口，不再只是纵向卡片列表。顶部提供“新建作品/导入小说”，主体使用作品卡片或紧凑表格展示标题、章节数、生成状态、更新时间和最近操作。点击作品进入工作台，删除和复制梗概保留在卡片的次级菜单中。

#### 项目详情/章节

改成作品上下文页：顶部为作品摘要和生成总进度；左侧为章节列表；中间为当前章节内容与视觉风格；右侧为章节资产摘要和任务状态。人物/场景提取作为章节级主操作，提取中、成功、失败和重试均在同一区域内显示。

#### 资产库

采用“筛选栏 + 资产网格 + 资产检查器”布局。筛选按人物、场景、作品、章节和状态组织；资产卡只显示缩略图、名称、类型、版本和更新时间。点击卡片后在右侧打开编辑检查器，支持保存、三视图生成、合并、复用和查看来源。大量资产时使用分页或分批加载，不把全部详细提示词一次性铺开。

#### 分镜工作台

采用“镜头轨道 + 当前镜头编辑区 + 输出检查器”布局。镜头轨道显示序号、时长、景别、首帧状态和视频状态；中间编辑区显示分镜脚本、对白/音效/音乐等现有信息，并把首帧和参考资产放入同一制作单元；右侧显示当前镜头的参考人物/场景和任务。底部固定显示生成首帧、上传首帧、保存、生成视频等当前可执行操作。

#### 视频生成

不再重复渲染一套分镜脚本。页面只负责视频输出：按镜头列出首帧缩略图、分辨率、当前视频、生成进度和历史版本。脚本内容通过折叠摘要引用分镜工作台的数据；生成失败就地显示失败原因、重试和安全改写操作。

#### 历史版本

按作品、章节、镜头组织历史资源。支持查看当前版本、切换当前版本、删除视频版本；历史页只做版本浏览和恢复，不复制完整的编辑逻辑。

## 核心组件

- `workspace-shell`：统一导航、顶部上下文、主内容槽位和响应式布局。
- `project-switcher`：作品/章节切换，支持 URL 参数同步。
- `status-badge`：状态文字、语义颜色和图标同时表达，不只依赖颜色。
- `task-list`：进行中、待处理、已完成、失败四种分组，显示阶段、耗时、对象和下一步。
- `asset-card` / `asset-inspector`：缩略图、类型、来源、版本、提示词编辑和操作。
- `scene-timeline` / `scene-editor`：镜头轨道、分镜信息、首帧和视频状态。
- `action-dock`：区域级主操作，按钮始终在当前可视区域内。
- `empty-state` / `error-state`：分别提供下一步引导和恢复操作。

组件使用原生 HTML/CSS/JavaScript 实现，先在共享文件中统一结构和样式，再由各页面脚本注入已有数据。这样不需要引入新的前端依赖。

## 数据与交互流程

1. 页面加载时解析 `novelId`、`chapterNum`，加载作品、章节、资产、分镜和任务摘要。
2. 用户从左侧或顶部切换上下文时同步更新 URL；刷新页面可恢复当前作品和章节。
3. 所有异步操作进入统一任务状态：立即显示“已提交”，超过 1 秒显示阶段文案，轮询完成后更新目标卡片和任务面板。
4. 失败信息显示在触发任务所在的卡片中，并提供与错误类型匹配的操作：重试、安全改写后重试、补充首帧、查看详情或返回分镜。
5. 保存操作禁用重复提交，并在保存完成后显示“已保存”时间；网络失败保留用户当前编辑内容。
6. 资产和视频版本切换后刷新当前检查器，不离开工作台。

## 响应式规则

- `>=1200px`：左导航、中间主画布、右检查器三列。
- `720px–1199px`：左导航缩窄，右检查器转为可展开抽屉。
- `<720px`：单列布局；导航改为顶部/底部可收起栏；所有主操作按钮全宽排列。
- 所有 Grid/Flex 子项设置 `min-width: 0`，长脚本、错误文本和资产名称允许换行。
- 粘性操作栏不遮挡输入框和焦点环，不使用会造成横向滚动的固定宽度。

## 视觉与可访问性方向

采用浅色专业创作工具风格，而不是营销页：低对比背景、清晰边界、紧凑间距、单一主操作色和语义状态色。参考用户给出的“梦境文阁”页面，只借鉴轻盈的渐变、圆角和创作工具氛围，不照搬彩色营销按钮堆叠，避免降低信息可读性。

- 主文字与背景对比度至少 4.5:1。
- 控件命中区域至少 44×44px。
- 图标按钮提供 `aria-label`，状态同时提供文本。
- 异步状态通过 `aria-live="polite"` 更新。
- 支持键盘导航、Escape 关闭抽屉，保留可见焦点环。
- 动效仅用于抽屉、状态切换和反馈，支持 `prefers-reduced-motion`。

## 实施顺序

1. 建立共享工作台壳层、设计令牌和状态组件。
2. 重做作品历史、项目详情和资产库布局，验证项目/章节/资产数据链路。
3. 重做分镜工作台，把首帧与视频操作归入镜头制作单元。
4. 重做视频生成与历史版本，复用分镜和任务组件，移除重复脚本展示。
5. 保留旧页面备份，更新入口链接和兼容跳转。
6. 使用现有前端测试、Maven 测试和浏览器实际页面逐项验证。

## 验收标准

- 所有现有页面仍可通过原 URL 打开。
- 所有原有 API 操作入口仍可用，异步任务不会因布局重排丢失状态。
- 用户可以从历史作品进入章节，再进入资产、分镜和视频生成，过程中无需重复选择作品。
- 分镜页面不再重复显示同一份脚本；视频页面只显示输出和版本信息。
- 资产、任务、错误、空数据和加载中状态均有明确展示。
- 1440px、1024px、720px、375px 视口无横向滚动，主操作按钮不跑出可视区域。
- 旧页面文件保留，且新页面的布局调整不影响后端接口与数据库数据。
