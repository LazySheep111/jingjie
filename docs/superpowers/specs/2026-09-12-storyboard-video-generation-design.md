# 分镜视频生成设计

## 1. 目标

在当前章节的分镜脚本全部可见后，用户可以从分镜脚本面板进入当前章节的视频生成页。每个分镜独立生成一个视频，并使用该分镜关联的人物和场景三视图作为参考，同时自动加入全书视觉风格。视频生成采用异步任务，结果保存到本地并保留历史版本。

本设计只处理当前章节，不提供整章一次性生成按钮。

## 2. 已确认的交互决策

- “前往视频生成”放在分镜脚本面板顶部操作区：`生成分镜脚本`、`保存分镜修改`、`前往视频生成`、`导出 TXT`。
- 页面入口为 `/video-generation.html?novelId={novelId}&chapterNum={chapterNum}`。
- 发现未保存修改时弹窗提供“保存并前往视频生成”“不保存直接前往”“取消”。
- 视频生成页只展示当前章节。
- 每个分镜拥有独立的“生成视频”按钮，互不阻塞，支持单独重试。
- 每次生成产生新版本，旧版本保留；历史版本放在当前分镜内部折叠展示。
- 缺少人物或场景三视图时阻止生成并提示用户补齐资产。
- 每个分镜只传入它关联的三视图，每张图片独立传入。
- 如果视频模型不支持多张参考图，直接停止生成并提示，不自动合并、不只取第一张。
- 视频请求自动加入全书视觉风格。
- 视频文件保存到本地 `novel/uploads/videos/`。

## 3. 页面结构

页面顶部显示小说名、章节名和分镜总数，并提供“返回分镜编辑”和“刷新状态”。

每个分镜使用可展开面板，包含：

- 分镜编号、时长、景别
- 分镜位置、时间、镜头运动
- 视频提示词、画面描述、人物动作、对白
- 当前视频预览
- 关联人物三视图和场景三视图
- 当前任务状态
- “生成视频”或“重新生成视频”按钮
- “下载视频”按钮
- 折叠的历史版本列表

状态文案：

```text
未生成 -> 排队中 -> 生成中 -> 生成成功
                         \-> 生成失败
```

失败状态必须展示可读错误原因，并提供“重新生成视频”。

## 4. 数据模型

### 4.1 `video_generation_task`

记录一次分镜视频生成任务：

| 字段 | 说明 |
| --- | --- |
| id | 任务 ID |
| novel_id | 小说 ID |
| chapter_num | 章节号 |
| storyboard_scene_id | 分镜 ID |
| status | `QUEUED`、`RUNNING`、`SUCCESS`、`FAILED` |
| provider_task_id | 视频模型任务 ID，可为空 |
| error_message | 失败原因 |
| created_at | 创建时间 |
| updated_at | 更新时间 |

### 4.2 `storyboard_video`

记录视频文件和版本：

| 字段 | 说明 |
| --- | --- |
| id | 视频 ID |
| novel_id | 小说 ID |
| chapter_num | 章节号 |
| storyboard_scene_id | 分镜 ID |
| version | 分镜内递增版本号 |
| video_path | 本地相对路径 |
| duration_sec | 视频时长 |
| prompt_snapshot | 生成时使用的提示词快照 |
| style_snapshot | 生成时使用的全书风格快照 |
| is_current | 是否为当前展示版本 |
| created_at | 创建时间 |

### 4.3 `storyboard_video_asset`

记录生成视频时使用的资产快照：

| 字段 | 说明 |
| --- | --- |
| video_id | 视频 ID |
| asset_id | 资产 ID |
| asset_version | 资产版本 |
| asset_name | 资产名称快照 |
| asset_type | `CHARACTER` 或 `LOCATION` |
| image_path | 三视图路径快照 |

## 5. 后端接口

### 创建任务

```http
POST /api/novel/{novelId}/chapters/{chapterNum}/storyboard/{sceneId}/video-tasks
```

请求：

```json
{
  "sceneId": 1
}
```

服务端读取分镜、全书风格和关联资产，完成校验后返回：

```json
{
  "taskId": 1001,
  "status": "QUEUED"
}
```

### 查询任务

```http
GET /api/video-tasks/{taskId}
```

成功示例：

```json
{
  "taskId": 1001,
  "status": "SUCCESS",
  "videoId": 2001,
  "videoUrl": "/uploads/videos/53/chapter_1/scene_1/v1.mp4",
  "errorMessage": null
}
```

### 查询视频版本

```http
GET /api/novel/{novelId}/chapters/{chapterNum}/storyboard/{sceneId}/videos
```

返回当前版本和历史版本列表。

### 重试任务

```http
POST /api/video-tasks/{taskId}/retry
```

重试应创建新的任务记录，不修改原失败任务。

### 切换当前版本

```http
PUT /api/storyboard-videos/{videoId}/current
```

只切换展示版本，不删除任何历史视频。

## 6. 服务端执行流程

1. 接收当前分镜 ID并创建 `QUEUED` 任务。
2. 校验分镜存在且关联资产完整。
3. 校验所有关联资产存在有效三视图路径。
4. 读取全书视觉风格并生成最终提示词。
5. 创建 `RUNNING` 状态并调用视频模型适配器。
6. 将每张三视图作为独立参考图传入。
7. 如果模型明确不支持多张参考图，任务失败并返回可读错误。
8. 获取模型返回的视频地址后下载到本地：

```text
novel/uploads/videos/{novelId}/chapter_{chapterNum}/scene_{sceneId}/v{version}.mp4
```

9. 保存视频、提示词、风格和资产快照。
10. 将新版本设为当前版本，旧版本取消当前标记。
11. 前端轮询到 `SUCCESS` 后显示视频。

视频模型调用应通过独立的 `VideoGenerationClient` 接口封装，具体厂商请求格式放到实现类和配置中，避免前端或业务服务绑定供应商。

## 7. 前端轮询

- 点击按钮后立即显示“排队中”。
- 轮询间隔建议 2 秒。
- 状态为 `QUEUED` 或 `RUNNING` 时继续轮询。
- `SUCCESS` 时停止轮询并加载视频。
- `FAILED` 时停止轮询并显示错误和重试按钮。
- 页面刷新后，根据分镜查询现有任务和视频版本，恢复状态。

## 8. 异常规则

- 未保存分镜：由入口弹窗决定保存、放弃或取消。
- 缺少三视图：不调用视频模型，提示缺失资产名称。
- 图片路径不存在：任务失败并记录具体路径。
- 多图能力不支持：任务失败，不自动改变参考图集合。
- 模型返回地址下载失败：不创建成功视频版本，任务标记失败。
- 轮询超时：前端显示“任务状态读取超时”，允许重新查询，不立即删除任务。
- 重试：保留原任务和原视频，创建新的任务或新版本。

## 9. 验收标准

- 每个分镜都有独立的生成按钮。
- 点击分镜 1 不会生成分镜 2。
- 一个分镜失败不影响其他分镜。
- 缺少三视图时不会调用视频模型。
- 视频请求包含全书视觉风格。
- 视频请求只包含当前分镜关联的参考图。
- 生成成功的视频刷新页面后仍可播放。
- 重新生成不会删除旧视频。
- 可以查看和切换历史版本。
- 视频模型不支持多张参考图时，页面展示明确错误，不降级为错误的参考图集合。

## 10. 范围边界

第一版不包含：

- 整章一键生成连续视频
- 多个分镜自动拼接成完整视频
- 云对象存储
- 视频后期剪辑
- 视频模型自动切换
- 多张参考图自动合成
