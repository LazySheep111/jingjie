# 视频分辨率选择设计

## 目标

为每个分镜的视频生成增加分辨率选择，并将用户选择真实传递给视频模型；同时在视频历史记录中保存并展示实际使用的分辨率。

## 用户体验

- 每个分镜独立显示“视频分辨率”下拉框。
- 选项统一展示为 `720P`、`768P`、`1080P`、`2K`。
- 默认值为 `768P`。
- 用户点击“生成视频”时，使用当前分镜下拉框的值。
- 历史视频显示版本、分辨率和时长，例如：`v1 · 768P · 4秒`。

## 后端规则

- 视频生成请求增加 `resolution` 字段。
- 当前 MiniMax-H3 仅允许 `768P` 和 `2K`。
- 其他模型根据现有模型能力开放对应分辨率；不支持的值不能提交给模型。
- 非法或缺失值回退到 `768P`。
- MiniMax 请求体将 `resolution` 写入模型的同名字段。
- 生成任务和视频历史记录保存本次分辨率，保证重试和历史查看可追溯。

## 数据流

1. 前端从分镜卡片读取分辨率。
2. 创建视频任务 API 接收并校验 `resolution`。
3. 服务层将分辨率写入任务快照和视频记录。
4. 视频客户端根据 provider/model 能力构造请求。
5. 页面轮询任务状态，并从历史记录显示分辨率。

## 兼容与错误处理

- 旧任务没有分辨率时，页面显示 `未知分辨率`，不影响播放。
- 不支持的分辨率在前端禁用或提示，后端再次校验。
- 模型返回错误时沿用现有任务失败流程，不产生成功的视频记录。

## 测试范围

- DTO、控制器和服务层传递分辨率。
- MiniMax 请求包含用户选择的分辨率。
- MiniMax-H3 拒绝 `720P`、`1080P` 并回退或提示，允许 `768P`、`2K`。
- 历史记录返回并展示分辨率。
- 前端默认值、选择值和提交字段存在。
