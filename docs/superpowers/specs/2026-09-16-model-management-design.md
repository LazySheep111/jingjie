# 模型管理栏设计

## 背景与目标

为 AI 视频创作工作台增加一个独立的模型管理入口。用户可以在前端配置文本、图片、视频三类 AI 服务的服务商、API 地址、API Key 和模型名称，并通过测试连接后保存启用。现有创作功能和已有 `application.properties` 配置必须继续可用。

## 页面与交互

- 左侧工作区导航最底部增加“模型管理”。
- 新增独立页面 `/model-management.html`，不把长配置表单塞进创作页面。
- 页面以三个配置卡展示固定能力槽位：文本模型、图片模型、视频模型。
- 每张卡提供服务商类型、API 地址、API Key、模型名称、连接状态、最近测试时间，以及“测试连接”“保存并启用”“停用模型”操作。
- API Key 输入框使用密码控件；已保存的 Key 只显示脱敏值。
- 宽屏使用三列卡片布局，小屏使用单列布局，按钮和错误信息不得发生横向溢出。

## 能力映射

| 能力槽位 | 当前系统消费者 | 默认接口形态 |
| --- | --- | --- |
| 文本模型 | 小说大纲、正文、分镜和提示词 | OpenAI 兼容聊天接口 |
| 图片模型 | 人物/场景三视图、分镜首帧 | OpenAI 兼容图片接口 |
| 视频模型 | 分镜视频生成 | Ark 或 MiniMax 专用请求格式 |

视频模型配置卡必须选择 Ark 或 MiniMax，后端根据服务商选择对应的请求体和任务查询逻辑。文本和图片模型允许自定义 OpenAI 兼容 API 地址。

## 数据模型

新增 `ai_model_config` 配置表。每次保存并启用创建一个新版本，旧版本停用但不物理删除，便于审计和回滚。

建议字段：

- `id`
- `capability_type`：`TEXT`、`IMAGE`、`VIDEO`
- `provider_type`
- `api_url`
- `encrypted_api_key`
- `model_name`
- `enabled`
- `test_status`
- `last_test_at`
- `last_error`
- `version`
- `created_at`
- `updated_at`

API Key 使用 AES-GCM 加密保存，加密主密钥从服务器环境变量读取。日志、异常和接口响应不得包含明文 API Key。

## 后端接口

- `GET /api/model-configs`：返回三个能力槽位的当前脱敏配置。
- `POST /api/model-configs/{type}/test`：使用本次表单内容测试，不写入数据库。
- `PUT /api/model-configs/{type}`：校验并保存新版本，同时启用该版本。
- `POST /api/model-configs/{type}/disable`：停用当前配置。

当数据库没有启用配置时，AI 调用继续读取现有 `application.properties`。数据库配置启用后优先使用数据库配置，保证平滑迁移和旧环境兼容。

## 测试连接策略

- 文本模型发送极短请求，验证地址、Key 和模型是否可用。
- 图片模型只做 URL、参数和接口可达性检查，不生成图片。
- 视频模型只做 URL、参数和接口可达性检查，不提交视频任务。
- 页面明确提示真实生成可能产生第三方费用。
- 测试失败时不覆盖当前已启用配置。

## 前端状态与错误反馈

配置卡状态包括：未配置、已配置未测试、测试中、测试成功、测试失败、已启用、已停用。

错误应显示在对应配置卡内，包含用户可理解的原因和下一步建议；保存、测试和停用按钮在请求期间进入明确的忙碌/禁用状态。成功后更新卡片状态和更新时间，不刷新整个页面。

## 验收标准

1. 六个工作台页面都能看到位于导航最底部的“模型管理”，原有链接和选中状态不受影响。
2. 模型管理页可以分别读取和编辑文本、图片、视频三个配置。
3. API Key 在数据库中不是明文，查询接口不返回完整 Key。
4. 测试连接不会生成图片或视频，也不会覆盖当前配置。
5. 保存并启用后，后续对应能力优先使用数据库配置。
6. 没有数据库配置时，现有 `application.properties` 行为保持不变。
7. 桌面端和移动端均无按钮挤压、横向溢出或敏感信息泄露。
8. 为表、接口、加密、服务商适配和前端交互补充自动化测试，并运行现有前端检查和 Maven 测试。
